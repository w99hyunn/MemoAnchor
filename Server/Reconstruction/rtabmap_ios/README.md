# Native RTAB-Map iOS Integration

This path is for the in-app scanner, not the old upload-to-server reconstruction
loop.

The intended runtime path is:

1. Unity ARFoundation owns the iOS `ARSession`.
2. `ARKitMeshScanController` starts `MemoAnchorRtabmapNative`.
3. `MemoAnchorRtabmapUnity.mm` reads `ARSession.currentFrame` directly.
4. The native plugin forwards ARKit pose, YUV camera image, LiDAR scene depth,
   confidence, feature points, camera intrinsics, and projection metadata to
   RTAB-Map's official iOS `postOdometryEventNative()` entry point.
5. On stop, Unity asks RTAB-Map to export a textured OBJ under
   `Application.persistentDataPath/NativeRtabmap/<scanId>/`.

This avoids the previous failure mode where Unity saved loosely synchronized
RGB/depth/pose files and the Python server tried to reconstruct them later.

## Fetch RTAB-Map

```bash
cd <repo-root>
bash Server/Reconstruction/rtabmap_ios/fetch_rtabmap_ios.sh
```

That places the upstream source at:

```text
Server/Reconstruction/rtabmap_ios/vendor/rtabmap/app/ios
```

## Build Dependencies

RTAB-Map's iOS app ships its dependency installer:

```bash
cd Server/Reconstruction/rtabmap_ios/vendor/rtabmap/app/ios/RTABMapApp
bash install_deps.sh
```

Then open:

```text
Server/Reconstruction/rtabmap_ios/vendor/rtabmap/app/ios/RTABMapApp.xcodeproj
```

Build the official app once on the target LiDAR iPhone/iPad. This validates the
device, Xcode signing, dependency build, ARKit scene depth support, and RTAB-Map
export path before Unity is involved.

## Unity Link Step

The Unity plugin file is already present:

```text
Assets/Plugins/iOS/MemoAnchorRtabmapUnity.mm
```

It intentionally compiles as a stub until the RTAB-Map iOS headers/libs are
linked into the generated Unity Xcode project. After linking, the compile-time
check `__has_include("NativeWrapper.hpp")` flips the plugin to the real native
RTAB-Map path.

Minimum files/symbols needed from RTAB-Map iOS:

- `app/ios/RTABMapApp/NativeWrapper.hpp`
- `app/ios/RTABMapApp/NativeWrapper.cpp`
- the RTAB-Map app/core static libraries and headers generated by its iOS build

At runtime the Unity HUD shows:

```text
Native RTAB-Map: recording <n> frame(s), rejected <n>
```

If it shows that RTAB-Map is not linked, the Unity side is wired but the Xcode
target still needs the RTAB-Map native build products.
